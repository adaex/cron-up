# 旧版迁移

本文适用于从 **26.10.30 及更早版本**升级到 **26.10.31 或更高版本**。从 26.10.31 开始，预热模型由“每个目录一个会话”改为“每个进入窗口的任务一个会话”，配置也只保留 roots

## 主要变化

| 方面 | 26.10.30 及更早 | 26.10.31 起 |
| --- | --- | --- |
| 预热粒度 | 每个工作区一个目录级会话 | 每个进入窗口的任务一个专属会话 |
| 会话日志 | 目录级命名 | `<工作区折名>--<任务id>.log` |
| 状态记录 | 扁平的目录级条目 | 按工作区、任务 id 两级记录 |
| 配置 | 可能留有旧行为开关和字段 | 只保留 `roots`，其他行为常量化 |

## 升级步骤

通用安装、启动链重建和总览验收按 [README 的升级步骤](../README.md#升级与启动链维护)执行。刚发布、需要避免 registry 或本机缓存带回旧版时，按[发布后的逐机升级与验收](release.md#每次发版后的逐机升级与验收)使用显式版本号

重跑 install 会移除旧版废弃配置字段；配置无法解读时的默认 roots 回退与首轮写入风险见 [README 的配置恢复说明](../README.md#配置无法解读时)

迁移后还要检查预热日志名称。新一代任务级日志应包含 `--<任务id>`；`cron-up logs <目录名>` 命中多个任务时，按候选提示补充任务 id

## 旧目录级会话如何收尾

升级后的首轮巡检会结束能够核实身份的旧目录级预热，再按任务重新启动。迁移不会把旧的目录级状态直接伪装成新任务级状态

为防止 pid 复用导致误杀，缺少进程启动指纹的旧条目不会被贸然发信号：

- 对应进程已经退出时，不再需要停止它
- 对应进程仍在运行且无法安全核实时，巡检会明确告警并保留旧状态，在后续轮次重试，不会把“未停止”记成“已回收”
- 出现这类告警时，先用 `cron-up logs` 找到“旧版迁移”条目，记录其中的 pid、工作区或日志路径；旧版扁平状态不一定会出现在总览中
- 再把下列命令中的 12345 换成实际 pid，核对进程启动时间、父进程和完整启动命令：

  ```bash
  /bin/ps -p 12345 -o pid=,ppid=,lstart=,args=
  ```

  确认它确为旧版预热后再决定如何收尾；无法确认身份时，不要对该进程或其进程组直接发信号

## 不会自动回滚的内容

升级和卸载都不会把任务文件恢复到首次使用 cron-up 之前：

- 已写入的 `permanent` 会保留
- 已改写的 `createdBySessionId`、`createdByPid`、`createdByProcStart` 不会自动还原
- Claude Code 的任务和 `~/.claude/projects` 下的对话记录不由迁移流程删除

如果工作区不再纳入 roots，后续巡检不会再维护它，但既有字段和已经运行且失去扫描视野的会话仍需分别核查
